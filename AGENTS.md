# ai_chess — состояние и правила работы

## Решения
- Python 3.10+, PySide6 и python-chess уже установлены. Не переустанавливать без необходимости.
- C++23, CMake, компилятор clang++-20; протокол UCI, собственные правила в C++.
- GUI проверяет пользователь вручную. Агент проверяет ядро, протокол, журналы и CLI автоматически.
- Пользователь запретил запуск тестов вне песочницы. LeakSanitizer здесь несовместим с ptrace; использовать ASAN_OPTIONS=detect_leaks=0, не запрашивать выход из песочницы.
- Локальные socket.send запрещены песочницей; SimpleEngine зависает на пробуждении asyncio. Используется собственный UCI-транспорт по каналам, python-chess остаётся независимым арбитром и PGN-парсером.
- GUI должен запускаться в совместимом Python: установленный PySide6 6.12.0 теряет ссылки на None под Python 3.10. Подготовлено .venv на имеющемся Python 3.12.15 с ссылками на существующие chess/PySide6/shiboken6, без скачиваний или глобальной переустановки. python3 -m ai_chess проверяет Qt и автоматически переключается на .venv; CLI Qt не импортирует.
- Дебютная книга собирается только из собственных партий; стандартные окончания добавляются после основной версии.
- После каждого этапа обновлять этот файл и соответствующий документ в plans/.

## Исправление none_dealloc (2026-10-14)
- Полный стек пользователя указывает на drawText в paintEvent; потоки UCI в это время ожидают stdin/stdout и команды человека.
- Воспроизведение без окна: 100 QObject.setObjectName() уменьшают refcount(None) ровно на 100 под Python 3.10.12; QFont/QPainter также теряют ссылки. Ошибка установленной сборки Qt, не памяти C++-движка.
- Python 3.12.15 уже был установлен. .venv использует существующие пакеты abi3 и чистый chess через ссылки; повторное создание: python3 tools/create_gui_env.py. Скрипт не скачивает пакеты и не меняет глобальное окружение.
- ai_chess/qt_runtime.py проверяет Qt до создания виджетов, запрещает запуск несовместимых bindings или переключает CLI-запуск GUI на проверенное .venv. Не изменять refcount Python вручную и не маскировать проблему удержанием None.
- 17 тестов прошли; новая регрессия проверяет 50000 вызовов QtCore/QtGui без окна и без потери ссылок. Проверены диагностическое завершение и сохранение аргументов при переключении.
- Старая зависимость python-chess UCI продолжает использоваться только в отдельном асинхронном тесте; рабочий транспорт по каналам не менялся.
- Пользователь повторно проверил приложение после исправления: полная партия завершилась победой компьютера без сообщённого повторного падения. PGN logs/games/20261014_205935_993502_df8f6d29.pgn: Human — ai_chess 0.1, 0-1, checkmate, 23...Qxe1#, 46 полуходов, 1 секунда на ход. Ручная проверка исправления выполнена.

## Ограничения
- GUI и полная партия после исправления none_dealloc проверены пользователем. Это подтверждает работоспособность проверенного сценария, но не является гарантией отсутствия всех ошибок.
- Слабый базовый движок; нет рейтинга, точных таблиц, шахматных часов, Chess960, ponder и параллельного поиска.
- По глубине без лимита времени действует защитный таймаут контроллера 60 секунд. По времени — лимит + 5 секунд.
- Дебютная книга строится из собственных законченных партий двух движков, без технических поражений. Разнообразие исходных партий пока ограничено.
