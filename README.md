# ai_chess

Шахматный движок на C++23 и приложение на Python/PySide6. Можно играть мышью против движка, наблюдать за двумя UCI-процессами, запускать серии без окна и просматривать сохранённые партии.

## Сборка и запуск

В текущей системе уже установлены Python 3.10, PySide6 и python-chess. CMake-пресеты используют `clang++-20` и Ninja.

```bash
cmake --preset release
cmake --build --preset release -j 4
python3 -m ai_chess
```

Команды выполняются из корня репозитория. Установка Python-пакета для этого не требуется. В окне выберите режим, пути к движкам и нажмите «Новая партия». Фигуру и клетку назначения выбирают двумя щелчками мышью. Превращение предлагает четыре фигуры. Для игры за чёрных доска автоматически переворачивается.

В текущей системе установленная сборка PySide6 6.12.0 теряет ссылки на `None` при запуске на Python 3.10 и приводит к `Fatal Python error: none_dealloc`. Это воспроизведено на `QObject.setObjectName()` без окна. Перед запуском GUI приложение проверяет совместимость и автоматически переключается на подготовленное `.venv` с Python 3.12. CLI-серии не требуют Qt и могут использовать системный Python.

Локальное окружение использует уже установленные пакеты `chess`, `PySide6` и `shiboken6` через ссылки; глобальные библиотеки не изменялись, скачивания не нужны. Для восстановления окружения выполните из системного Python, в котором установлены библиотеки:

```bash
python3 tools/create_gui_env.py
.venv/bin/python -m ai_chess
```

Скрипт требует имеющийся `python3.12`, сохраняет существующее окружение с другой версией Python без изменений и проверяет совместимость перед завершением. Если безопасное окружение отсутствует, приложение выводит понятную ошибку до создания GUI. После изменения/перемещения исходных пакетов ссылки окружения также нужно проверить.

По умолчанию используется `build/release/ai_chess_engine` и одна секунда на ход. Ноль в GUI отключает соответствующее ограничение времени или глубины; хотя бы одно должно быть включено. Пауза применяется между ходами движков, поэтому уже вычисляемый ход может завершиться и появиться на доске. Остановка/новая партия прерывает текущий процесс и сохраняет незавершённую партию.

## Серии без GUI

```bash
python3 -m ai_chess match --games 10 --time 0.1 --depth 4
python3 -m ai_chess match --white build/release/ai_chess_engine --black /path/to/other/uci-engine --games 4
python3 -m ai_chess match --depth 3 --max-plies 400 --logs logs/experiment
```

Движки меняются цветами через партию; `--no-alternate` отключает это. Если задана только глубина, лимит времени на ход отключается. Защитный таймаут Python — время хода плюс 5 секунд, а при ограничении только глубиной — 60 секунд. Таймаут, сбой или нелегальный ход даёт техническое поражение и ненулевой код выхода серии. Ошибка запуска прерывает серию. Ctrl+C сохраняет текущую партию как прерванную.

Поддерживаются обычные шахматы, включая рокировку, взятие на проходе и все превращения. Мат/пат, недостаточный материал и автоматические заявления ничьей по повторению/50 ходам проверяются Python. Автоматическое заявление также учитывает возможность заявить ничью следующим ходом. Это выбранная политика приложения. Защитный предел по умолчанию — 400 полуходов; при его достижении партия остаётся с результатом `*`, а не считается шахматной ничьей.

Полные шахматные часы, Chess960 и `ponder` в первой версии не реализованы. UCI-движок поддерживает `go depth`, `go movetime`, их сочетание, `go infinite` и `stop`; контроллер передаёт именно эти ограничения.

## Журналы

Каждая партия хранится отдельным PGN в `logs/games/`. Файл атомарно обновляется после каждого хода; в заголовках есть локальное и UTC-время начала, часовой пояс, пути и имена движков, лимиты, seed, результат и причина окончания. При ошибках рядом сохраняется `.stderr.log` с диагностикой и stderr движков. Незавершённые партии имеют результат `*`.

Во вкладке «Журналы и просмотр» нажмите «Обновить журналы» или откройте внешний PGN. Доступны список ходов, переход к началу/концу и воспроизведение. Просмотр не запускает движки. Запись незавершённой партии сохраняет её историю, но возобновление игры из журнала в этой версии не предусмотрено.

## Дебютная книга из собственных партий

Сначала накопите законченные партии двух движков. Прерванные партии, технические поражения и партии человека исключаются из обучения.

```bash
python3 -m ai_chess match --games 20 --time 0.05
python3 -m ai_chess export-book --logs logs/games --output books/own-games.txt
build/release/chess_book books/own-games.txt books/own.book
python3 -m ai_chess match --games 10 --book books/own.book --seed 42
```

GUI позволяет указать путь к книге и seed. Экспортёр Python проверяет PGN и переводит партии в последовательности UCI-ходов. C++-сборщик повторно проверяет легальность, собирает первые 20 полуходов и статистику побед/ничьих/поражений относительно стороны, делающей ход. Книга учитывает транспозиции. Выбор хода взвешен по результатам и частоте; фиксированный seed воспроизводит выбор при одинаковой последовательности запросов. Записи книги дополнительно фильтруются по легальным ходам. При отсутствии записи выполняется обычный поиск.

Формат входа: первая строка `AI_CHESS_OWN_GAMES 1`, далее строки `результат ход ход ...`. Формат книги: `AI_CHESS_BOOK 1`, далее `ключ move16 победы ничьи поражения`. Ключи используют фиксированные Zobrist-таблицы; изменение схемы ключей требует новой версии формата и пересборки книги. Внешние PGN не используются для обучения. Качество книги зависит от качества и разнообразия собственных партий; книга не заменяет поиск.

## Архитектура

- `cpp/`: самостоятельные правила, битовые доски и массив клеток, компактные ходы, обратимое применение, Zobrist-ключи; поиск negamax/alpha-beta с итеративным углублением, quiescence и ограниченной таблицей транспозиций. История повторений и счётчик 50 ходов участвуют в ключе поисковой таблицы.
- `ai_chess/`: независимый контроллер на python-chess, UCI-адаптер, атомарные журналы, CLI и GUI. Расчёт и запись файлов выполняются в рабочем потоке Qt; результаты старой партии отбрасываются по её поколению.
- `tests/`: CTest и независимые проверки Python без GUI.

Движок первоначально однопоточный. UCI-команды читает основной поток, поиск работает отдельно. `Hash` задаёт 1–256 MiB (по умолчанию 16); `OwnBook`, `BookFile`, `Seed` управляют книгой. Оценка включает материал, таблицы положения фигур, проходные пешки, активность короля в окончаниях и вытеснение одинокого короля к краю в окончаниях с ладьёй/ферзём. Это эвристики, а не точные таблицы окончаний.

## Проверки

```bash
cmake --preset debug
cmake --build --preset debug -j 4
ctest --preset debug
python3 -m unittest discover -s tests -p 'test_*.py' -v

cmake --preset sanitize
cmake --build --preset sanitize -j 4
ASAN_OPTIONS=detect_leaks=0 ctest --preset sanitize
```

Python-тесты по умолчанию используют Release. Для другого бинарного файла задайте `CHESS_ENGINE=build/debug/ai_chess_engine` (абсолютный путь также допустим).

В текущей песочнице LeakSanitizer не работает из-за `ptrace`; в приведённой команде отключена только проверка утечек. AddressSanitizer и UndefinedBehaviorSanitizer остаются включёнными. Все проверки выполняются внутри песочницы.

Транспорт UCI использует stdin/stdout и потоки чтения без asyncio: песочница запрещает отправку через локальные сокеты, необходимые фоновому `SimpleEngine` из python-chess. Проверка правил и PGN по-прежнему используют python-chess; совместимость движка с её асинхронным UCI-протоколом проверяется отдельно.

Диагностика ядра:

```bash
build/release/ai_chess_engine --perft 4
build/release/ai_chess_engine --inspect 'rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1' e2e4
```

`--inspect` выводит FEN, ключ позиции, признак текущей ничьей в C++ и набор легальных UCI-ходов. `--perft` не применяет правила окончания партии и считает дерево легальных ходов.

## Ручная проверка GUI

1. Сыграть за белых и чёрных: допустимые/недопустимые щелчки, шах, рокировка и превращение.
2. Запустить два движка, поставить паузу и продолжить, проверить задержку показа.
3. Начать новую партию во время расчёта: предыдущий ответ не должен менять новую доску.
4. Остановить партию и закрыть окно во время расчёта: процессы должны завершиться, PGN сохраниться.
5. Просмотреть журнал по ходам, перейти к началу/концу, проверить автоматическое воспроизведение.
6. Проверить сообщение о неверном пути к движку и повреждённом PGN.

Состояние работ и дальнейшие задачи находятся в `AGENTS.md` и `plans/`.

### Сбор книги и сравнение по времени

Для каждого прогона укажите новый каталог журналов. Все команды выполняются без GUI; требуется существующая Release-сборка. Длительность задаётся в секундах. Последняя партия при истечении времени сохраняется незавершённой и исключается из книги и результата матча.

```bash
# Пять минут само­игры без книги
python3 -m ai_chess match --duration 300 --time 0.05 --book '' --logs logs/stability-run

# Двадцать минут собственных партий, затем построение книги
python3 -m ai_chess train-book --duration 1200 --time 0.05 --seed 731 --logs logs/book-training-run --output books/own-20min.book

# Двадцать минут сравнения с заранее сохранённым исходным бинарником
python3 -m ai_chess compare-book --baseline /path/to/saved/ai_chess_engine --book books/own-20min.book --duration 1200 --time 0.05 --logs logs/book-comparison-run --activate-if-better

# Отдельные книги закреплены за участниками и меняются вместе с ними при смене цветов
python3 -m ai_chess match --games 10 --white-book books/own-20min.book --black-book '' --time 0.05
```

`match --duration` работает до истечения времени; если задан также `--games`, действует первое достигнутое ограничение. Старый `--book` задаёт общую книгу; `--white-book` и `--black-book` имеют приоритет, пустая строка отключает книгу у выбранного участника.

Сборщик исследует первые четыре полухода: собственный поиск глубины 3 оценивает продолжения, затем seed выбирает один из трёх лучших ходов в пределах 50 сантипешек от лучшего. Для матовых оценок выбираются только лучшие равные оценки. Далее оба движка играют обычным поиском. Время этого исследования включено в бюджет; построение книги выполняется после него. Используются только законченные партии данного прогона, до 20 полуходов каждой партии. Это статистическая книга из само­игры, её польза требует измерения.

Новые команды сохраняют `manifest.json` (параметры, пути и SHA-256 движков/книг), `progress.json`, `summary.json`, PGN и stderr. Обучающий экспорт `own-games.txt` позволяет повторно построить книгу. Уже существующие партии не смешиваются с новым экспериментом.

Сравнение проходит парами с перестановкой цветов и одинаковым seed внутри пары. Итог учитывает только полные пары законченных партий, показывает победы/ничьи/поражения, долю очков, результаты по цветам, разнообразие партий и 95%-й бутстрэп-интервал по парам. Технические сбои и незавершённые игры показываются отдельно. Время, сэкономленное книгой, оценивается как число обращений × лимит на ход минус фактическое время обращений; это номинальная оценка, а не измерение ускорения всего поиска. Фиксированный seed воспроизводит выбор при одинаковых оценках, но поиск по времени может различаться между запусками.

Флаг `compare-book --activate-if-better` подключает книгу по умолчанию только при подтверждённом улучшении: минимум 20 полных пар, 10 уникальных партий, отсутствие технических ошибок, фактическое использование книги и нижние 95%-е границы бутстрэпа и консервативной оценки Хёффдинга выше 50%. Настройка хранится в `books/default.json` и привязана к пути и SHA-256 проверенного движка и SHA-256 книги. Изменение движка или книги отключает автоматический выбор. GUI заполняет поле книги при запуске; для отключения очистите его. CLI `match --book ''` отключает общую стандартную книгу; явные настройки отдельных участников сохраняют приоритет. Сбор и контрольный участник сравнения всегда работают без стандартной книги.

Эксперимент 2026-10-14 завершён: книга из 187 партий (483 позиции, 551 запись хода) набрала 49,30% очков против исходного движка в 214 партиях при 0,05 с на ход; 95%-й интервал 45,56–53,27%. Усиление не подтверждено, книга не включена по умолчанию. [Подробный отчёт](plans/04-learning.md#итог-эксперимента-2026-10-14).

### Адаптивное обучение дебютам

```bash
# 40 минут обучения и 20 минут сравнения; требуется новый пустой каталог
python3 -m ai_chess.learning_experiment --logs logs/experiments/adaptive-openings-20261014 --history logs/experiments/openings-20261014/training

# Только адаптивный сбор, без автоматического сравнения и подключения
python3 -m ai_chess train-book --adaptive --duration 2400 --opening-plies 12 --opening-top 8 --time 0.05 --logs logs/adaptive-training --output books/adaptive.book
```

Адаптивный режим исследует первые 12 полуходов, до восьми продолжений в пределах 50 сантипешек по собственному поиску глубины 3. Неиспытанные ходы имеют приоритет; затем выбор учитывает результаты и бонус за недостаточную изученность. После проигрыша в первой исследованной позиции проигравшей стороны с альтернативой ход однократно пропускается при следующем посещении. Далее он снова доступен с учётом обновлённой статистики. Итог партии — слабый сигнал о качестве дебюта: поражение могло быть вызвано ошибкой позднее.

После каждой законченной партии сохраняется `learning.json` со статистикой и ожидающими переключениями. Прерванные и технические партии не дают обучающих результатов. `--history` принимает только прежнюю учебную серию того же движка и контроля; одинаковые полные партии истории учитываются один раз. Партии человека и прежние сравнительные матчи не используются. Продолжить накопление опыта можно новым прогоном с `--history` на каталог завершённого обучения; статистика пересчитывается из его PGN. История предыдущей истории автоматически не переносится.

Книга адаптивного режима охватывает исследованные полуходы: минимум шесть результатов на ход, сглаженная доля очков не дальше 0,05 от лучшего достаточно проверенного продолжения. В остальных позициях работает обычный поиск. У C++-сборщика доступны параметры `--max-plies 12 --min-games 6 --score-margin 0.05`; без них сохраняется прежнее поведение.

Общая команда сохраняет исходный движок и сборщик, контрольные суммы исходников, PGN, промежуточные и итоговые JSON, экспорт и `candidate.book`. Время исследования входит в 40 минут; подготовка, построение книги и отчёты выполняются дополнительно. Последующие 20 минут книга заморожена, кандидат играет против исходного движка без книги с перестановкой цветов. Подключение по умолчанию возможно только при выполнении прежних статистических критериев. `status.json` показывает текущий этап; итоги обучения содержат частоты первых ходов, число уникальных начал и переключений после поражений.

Адаптивный эксперимент 2026-10-14 завершён: за 40 минут получены 288 законченных партий с 288 уникальными началами на 12 полуходах и 192 переключениями после поражений. Но за 20 минут сравнения книга получила 9 побед и 193 поражения — **4,46% очков**. Она ослабила игру в этом локальном матче и **не подключена по умолчанию**. Данные и книга сохранены в `logs/experiments/adaptive-openings-20261014/`. [Полный результат и ограничения](plans/04-learning.md#итог-адаптивного-эксперимента).

### Обучение против фиксированного соперника

```bash
python3 -m ai_chess train-book --opponent build/release/ai_chess_engine --duration 3600 --time 0.05 --logs logs/fixed-training --output books/fixed.book

# Общий срок включает обучение, выбор глубины книги и итоговое сравнение
python3 -m ai_chess.fixed_experiment --logs logs/experiments/fixed-openings-20261015 --deadline-utc 2026-10-15T03:14:03Z
```

С `--opponent` дебюты исследует только кандидат, а соперник всегда играет обычным поиском без книги; цвета чередуются. Анализ продолжений выполняется отдельным процессом и не меняет состояние поиска участников. Статистика и книга включают только ходы кандидата. Старую историю само­игры этот режим не принимает. Экспорт `AI_CHESS_OWN_GAMES 2` сохраняет цвет кандидата; сборщик также понимает прежнюю версию 1.

Общая команда сохраняет бинарники, распределяет остаток времени до `--deadline-utc`: обучение, 30 минут отбора книг на 4/12 полуходах и до 45 минут независимого итогового сравнения; 2 минуты оставляет для аудита. Срок задаётся ISO 8601 с часовым поясом. Все этапы сохраняются отдельно, во время отбора/сравнения обучение отключено. Подключение книги возможно только по успешному финальному матчу и прежним строгим критериям. Прогресс в `status.json` и `progress.json` каталога текущего этапа.

Для нового прогона укажите новый каталог и будущий срок; дата в примере относится к завершённому эксперименту. `--no-activate` позволяет сохранить результат без изменения стандартной книги.

Пятичасовой цикл 2026-10-15 завершён в срок. Обучение дало 1922 законченные партии, 570 разных начал на 12 полуходах и 196 переключений после поражений. Выбрана книга на 12 полуходах: 33 позиции/50 ходов. В отдельном финальном матче против исходного движка при 0.05 с/ход она получила **633 победы, 8 ничьих и 1 поражение — 99.22% очков** в 642 зачётных партиях. Условия подключения выполнены; книга автоматически выбирается при новом запуске GUI/CLI и привязана к хешам. Для отключения очистите поле книги в GUI или используйте `match --book ''`.

Это измеренное преимущество против данного исходного движка при коротком контроле. Другие соперники и контроли требуют отдельной проверки. [Итог и аудит](plans/04-learning.md#итог-пятичасового-цикла).
