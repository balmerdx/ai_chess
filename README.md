# ai_chess

Шахматный движок на C++23 и приложение на Python/PySide6. Можно играть мышью против движка, наблюдать за двумя UCI-процессами, запускать серии без окна и просматривать сохранённые партии.

## Сборка и запуск

В текущей системе уже установлены Python 3.10, PySide6 и python-chess. CMake-пресеты используют `clang++-20` и Ninja.

```bash
cmake --preset release
cmake --build --preset release -j 4
python3 -m ai_chess
```

Команды выполняются из корня репозитория. Установка Python-пакета для этого не требуется. В окне выберите режим, пути к движкам и нажмите «Новая партия». Фигуру и клетку назначения выбирают двумя щелчками мышью. Превращение предлагает четыре фигуры. Для игры за чёрных доска автоматически переворачивается.

В текущей системе установленная сборка PySide6 6.12.0 теряет ссылки на `None` при запуске на Python 3.10 и приводит к `Fatal Python error: none_dealloc`. Это воспроизведено на `QObject.setObjectName()` без окна. Перед запуском GUI приложение проверяет совместимость и автоматически переключается на подготовленное `.venv` с Python 3.12. CLI-серии не требуют Qt и могут использовать системный Python.

Локальное окружение использует уже установленные пакеты `chess`, `PySide6` и `shiboken6` через ссылки; глобальные библиотеки не изменялись, скачивания не нужны. Для восстановления окружения выполните из системного Python, в котором установлены библиотеки:

```bash
python3 tools/create_gui_env.py
.venv/bin/python -m ai_chess
```

Скрипт требует имеющийся `python3.12`, сохраняет существующее окружение с другой версией Python без изменений и проверяет совместимость перед завершением. Если безопасное окружение отсутствует, приложение выводит понятную ошибку до создания GUI. После изменения/перемещения исходных пакетов ссылки окружения также нужно проверить.

По умолчанию используется `build/release/ai_chess_engine` и одна секунда на ход. Ноль в GUI отключает соответствующее ограничение времени или глубины; хотя бы одно должно быть включено. Пауза применяется между ходами движков, поэтому уже вычисляемый ход может завершиться и появиться на доске. Остановка/новая партия прерывает текущий процесс и сохраняет незавершённую партию.

## Серии без GUI

```bash
python3 -m ai_chess match --games 10 --time 0.1 --depth 4
python3 -m ai_chess match --white build/release/ai_chess_engine --black /path/to/other/uci-engine --games 4
python3 -m ai_chess match --depth 3 --max-plies 400 --logs logs/experiment
```

Движки меняются цветами через партию; `--no-alternate` отключает это. Если задана только глубина, лимит времени на ход отключается. Защитный таймаут Python — время хода плюс 5 секунд, а при ограничении только глубиной — 60 секунд. Таймаут, сбой или нелегальный ход даёт техническое поражение и ненулевой код выхода серии. Ошибка запуска прерывает серию. Ctrl+C сохраняет текущую партию как прерванную.

Поддерживаются обычные шахматы, включая рокировку, взятие на проходе и все превращения. Мат/пат, недостаточный материал и автоматические заявления ничьей по повторению/50 ходам проверяются Python. Автоматическое заявление также учитывает возможность заявить ничью следующим ходом. Это выбранная политика приложения. Защитный предел по умолчанию — 400 полуходов; при его достижении партия остаётся с результатом `*`, а не считается шахматной ничьей.

Полные шахматные часы, Chess960 и `ponder` в первой версии не реализованы. UCI-движок поддерживает `go depth`, `go movetime`, их сочетание, `go infinite` и `stop`; контроллер передаёт именно эти ограничения.

## Журналы

Каждая партия хранится отдельным PGN в `logs/games/`. Файл атомарно обновляется после каждого хода; в заголовках есть локальное и UTC-время начала, часовой пояс, пути и имена движков, лимиты, seed, результат и причина окончания. При ошибках рядом сохраняется `.stderr.log` с диагностикой и stderr движков. Незавершённые партии имеют результат `*`.

Во вкладке «Журналы и просмотр» нажмите «Обновить журналы» или откройте внешний PGN. Доступны список ходов, переход к началу/концу и воспроизведение. Просмотр не запускает движки. Запись незавершённой партии сохраняет её историю, но возобновление игры из журнала в этой версии не предусмотрено.

## Дебютная книга из собственных партий

Сначала накопите законченные партии двух движков. Прерванные партии, технические поражения и партии человека исключаются из обучения.

```bash
python3 -m ai_chess match --games 20 --time 0.05
python3 -m ai_chess export-book --logs logs/games --output books/own-games.txt
build/release/chess_book books/own-games.txt books/own.book
python3 -m ai_chess match --games 10 --book books/own.book --seed 42
```

GUI позволяет указать путь к книге и seed. Экспортёр Python проверяет PGN и переводит партии в последовательности UCI-ходов. C++-сборщик повторно проверяет легальность, собирает первые 20 полуходов и статистику побед/ничьих/поражений относительно стороны, делающей ход. Книга учитывает транспозиции. Выбор хода взвешен по результатам и частоте; фиксированный seed воспроизводит выбор при одинаковой последовательности запросов. Записи книги дополнительно фильтруются по легальным ходам. При отсутствии записи выполняется обычный поиск.

Формат входа: первая строка `AI_CHESS_OWN_GAMES 1`, далее строки `результат ход ход ...`. Формат книги: `AI_CHESS_BOOK 1`, далее `ключ move16 победы ничьи поражения`. Ключи используют фиксированные Zobrist-таблицы; изменение схемы ключей требует новой версии формата и пересборки книги. Внешние PGN не используются для обучения. Качество книги зависит от качества и разнообразия собственных партий; книга не заменяет поиск.

## Архитектура

- `cpp/`: самостоятельные правила, битовые доски и массив клеток, компактные ходы, обратимое применение, Zobrist-ключи; поиск negamax/alpha-beta с итеративным углублением, quiescence и ограниченной таблицей транспозиций. История повторений и счётчик 50 ходов участвуют в ключе поисковой таблицы.
- `ai_chess/`: независимый контроллер на python-chess, UCI-адаптер, атомарные журналы, CLI и GUI. Расчёт и запись файлов выполняются в рабочем потоке Qt; результаты старой партии отбрасываются по её поколению.
- `tests/`: CTest и независимые проверки Python без GUI.

Движок первоначально однопоточный. UCI-команды читает основной поток, поиск работает отдельно. `Hash` задаёт 1–256 MiB (по умолчанию 16); `OwnBook`, `BookFile`, `Seed` управляют книгой. Оценка включает материал, таблицы положения фигур, проходные пешки, активность короля в окончаниях и вытеснение одинокого короля к краю в окончаниях с ладьёй/ферзём. Это эвристики, а не точные таблицы окончаний.

## Проверки

```bash
cmake --preset debug
cmake --build --preset debug -j 4
ctest --preset debug
python3 -m unittest discover -s tests -p 'test_*.py' -v

cmake --preset sanitize
cmake --build --preset sanitize -j 4
ASAN_OPTIONS=detect_leaks=0 ctest --preset sanitize
```

Python-тесты по умолчанию используют Release. Для другого бинарного файла задайте `CHESS_ENGINE=build/debug/ai_chess_engine` (абсолютный путь также допустим).

В текущей песочнице LeakSanitizer не работает из-за `ptrace`; в приведённой команде отключена только проверка утечек. AddressSanitizer и UndefinedBehaviorSanitizer остаются включёнными. Все проверки выполняются внутри песочницы.

Транспорт UCI использует stdin/stdout и потоки чтения без asyncio: песочница запрещает отправку через локальные сокеты, необходимые фоновому `SimpleEngine` из python-chess. Проверка правил и PGN по-прежнему используют python-chess; совместимость движка с её асинхронным UCI-протоколом проверяется отдельно.

Диагностика ядра:

```bash
build/release/ai_chess_engine --perft 4
build/release/ai_chess_engine --inspect 'rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1' e2e4
```

`--inspect` выводит FEN, ключ позиции, признак текущей ничьей в C++ и набор легальных UCI-ходов. `--perft` не применяет правила окончания партии и считает дерево легальных ходов.

## Ручная проверка GUI

1. Сыграть за белых и чёрных: допустимые/недопустимые щелчки, шах, рокировка и превращение.
2. Запустить два движка, поставить паузу и продолжить, проверить задержку показа.
3. Начать новую партию во время расчёта: предыдущий ответ не должен менять новую доску.
4. Остановить партию и закрыть окно во время расчёта: процессы должны завершиться, PGN сохраниться.
5. Просмотреть журнал по ходам, перейти к началу/концу, проверить автоматическое воспроизведение.
6. Проверить сообщение о неверном пути к движку и повреждённом PGN.

Состояние работ и дальнейшие задачи находятся в `AGENTS.md` и `plans/`.
