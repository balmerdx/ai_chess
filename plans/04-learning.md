# Сессии 5–6: дебютная книга и окончания

Статус: реализованы первые версии; качество эвристик требует дальнейших измерений.

- Только собственные законченные партии двух движков; исключить технические поражения, человека и незавершённые игры.
- Python проверяет PGN и экспортирует ходы; C++ самостоятельно проверяет последовательности и строит статистическую книгу до 20 полуходов.
- Версионированный формат, статистика с точки зрения ходящей стороны, взвешенный выбор и seed; затем обычный поиск.
- Простые окончания: активный король и проходные пешки; для ладьи/ферзя против короля — край доски, расстояние между королями и уменьшение доступного прямоугольника.
- В quiescence простых окончаний разрешены два дополнительных тихих шаха: без этого на малой глубине возникали повторения вместо мата.
- Проверки: сборка/подключение книги, доведение контрольных ладейного, ферзевого и пешечного окончаний.

Будущие этапы: разнообразие собственных партий, более широкая выборка окончаний и точные таблицы. Текущие эвристики не дают гарантии идеальной игры во всех окончаниях.

## Эксперимент 2026-10-14: стабильность и собственная книга

План принят пользователем. Выполняются последовательно: 300 секунд само­игры исходной версии, 1200 секунд сбора собственных партий, 1200 секунд парного сравнения. Исходный Release-бинарник сохранён в `logs/experiments/openings-20261014/baseline/ai_chess_engine`; SHA-256 `b25d972aef0020f76c2c2bdca1f91cffff3fc3ac6d7f7ed819b6f92cc82306e6`.

Добавлены команды `train-book`, `compare-book` и `match --duration`. Новые эксперименты требуют отдельного пустого каталога; сохраняются PGN, manifest.json с хешами участников/книг, progress.json и summary.json. Длительность измеряется монотонными часами, таймер закрывает процессы на границе бюджета. Последняя партия сохраняется с `Result "*"`, `Termination "duration_limit"` и не участвует в обучении/оценке.

Обучение: первые четыре полухода выбираются по seed из трёх лучших продолжений в пределах 50 сантипешек от лучшего по собственному поиску глубины 3; матовые оценки не смешиваются. Затем обычный поиск по 0,05 секунды на ход. Время исследования входит в 1200 секунд; книга строится после завершения сбора из законченных партий этого прогона. Формат книги и C++-поиск не меняются.

Сравнение: фиксированная книга только у кандидата, сохранённый исходный движок без книги; пары с перестановкой цветов и одинаковым seed внутри пары. Учитываются только полные пары законченных партий. Технические ошибки, предел полуходов и прерванные партии показываются отдельно. Оценка: W/D/L, доля очков, цвета, разнообразие партий, 95%-й бутстрэп-интервал по парам (10000 выборок, seed 20261014). Для изменения стандартной книги дополнительно требуется консервативная нижняя граница Хёффдинга выше 50%, минимум 20 полных пар и 10 уникальных партий, отсутствие технических ошибок. Это более строгая проверка против вырожденных бутстрэп-интервалов при повторяющихся исходах. Интервалы описывают только локальный эксперимент, не мировой рейтинг.

Промежуточное состояние при запуске: пятиминутный прогон начат, семь новых автоматических проверок прошли. Все три этапа впоследствии завершены; итоговый отчёт ниже.

### Условия и результаты сравнения

Оба участника использовали один и тот же C++-движок: исходный бинарник сохранён до обучения, поиск и оценка не менялись. SHA-256 обоих бинарников: `b25d972aef0020f76c2c2bdca1f91cffff3fc3ac6d7f7ed819b6f92cc82306e6`. Различие — фиксированная книга только у кандидата. Лимит 0,05 с на ход без ограничения глубины, максимум 400 полуходов, стандартная начальная позиция, seed первой пары 12031; внутри пары одинаковый seed и перестановка цветов. Во время сравнения книга не обновлялась.

| Цвет кандидата с книгой | Партий | Доля очков |
| --- | ---: | ---: |
| Белые | 107 | 17.29% |
| Чёрные | 107 | 81.31% |
| Оба цвета | 214 | 49.30% |

В зачётной выборке 29 уникальных полных партий. Все 137 результативных партий выиграли чёрные, остальные 77 закончились ничьей. Перестановка цветов необходима для интерпретации результата; сравнивать только белую или чёрную сторону было бы недостаточно.

За весь сравнительный прогон зарегистрировано 2148 ходов из книги, суммарное время запросов 1.376 с. Номинальная экономия против выделенных 0,05 с на каждый такой ход — около 106.0 с за весь прогон. Это оценка экономии времени, не прирост силы. В режиме фиксированного времени на ход сэкономированное время не переносится на последующие ходы.

Оценка относится к этому сопернику, начальной позиции и короткому контролю. В выборке много повторов, а у книги ограниченное разнообразие. Это не рейтинг и не доказательство равенства при других настройках. Для дальнейшего улучшения стоит исследовать отбор ветвей книги и качество исходных партий; простое увеличение их количества само по себе здесь усиления не показало.

### Проверки и воспроизведение

Все **27 Python-тестов** прошли, включая реальные UCI-процессы, таймер и очистку, разделение книг, запасной поиск вне книги, фильтрацию PGN, учёт цветов/пар, статистический порог и привязку стандартной книги к хешам. CTest Debug и CTest ASan/UBSan прошли внутри песочницы с `ASAN_OPTIONS=detect_leaks=0`. GUI автоматически не запускался.

Журналы проверок и прогоны: [logs/experiments/openings-20261014/](../logs/experiments/openings-20261014/). Для каждого нового прогона нужен отдельный пустой каталог. Команды сбора и сравнения:

```bash
python3 -m ai_chess train-book --duration 1200 --time 0.05 --seed 731 --logs logs/new-training --output books/new-own.book
python3 -m ai_chess compare-book --baseline logs/experiments/openings-20261014/baseline/ai_chess_engine --book books/new-own.book --duration 1200 --time 0.05 --seed 12031 --logs logs/new-comparison --activate-if-better
```

Явное использование полученной книги: в GUI указать `books/own-20min.book` в поле книги; в CLI добавить `--book books/own-20min.book`. Без этого приложение продолжает использовать обычный поиск. Полные параметры, контрольные суммы и итоги доступны в `manifest.json`, `progress.json`, `summary.json` каталогов `training/` и `comparison/`; исходный тест стабильности — `stability.json` в корне эксперимента. Игровые данные и книги остаются локальными игнорируемыми артефактами; исходники, тесты и документация входят в изменения репозитория.
